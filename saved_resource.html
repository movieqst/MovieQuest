🏦 Multi-User PIN Vault

Each PIN unlocks a completely separate storage compartment. Like safety deposit boxes at a bank.

IndexedDB Structure
Object Store: files
Record Key: "user_1234"
→ Files for PIN 1234 (User A)
Record Key: "user_5678"
→ Files for PIN 5678 (User B)
Record Key: "user_9999"
→ Files for PIN 9999 (User C)
Each PIN = a unique prefix. Files are completely isolated by key.
db.files.get("user_" + enteredPin)

🔑 How It Works

1 User enters 4-digit PIN on the ATM-style keypad
2 App checks if a profile exists for that PIN. If not, creates a fresh empty one.
3 All file operations use that PIN as the namespace. User A never sees User B's files.
4 Log out → back to PIN screen. Next user enters their code → their own vault appears.
JavaScript — Multi-User File Save
// Current session PIN (set after successful login)
let activePin = null;

async function saveFile(fileBlob, fileName) {
  if (!activePin) return; // Must be logged in
  
  const userKey = `user_${activePin}`;
  
  // Get existing files for this user
  let userFiles = await db.files.get(userKey) || { files: [] };
  
  // Add new file
  userFiles.files.push({
    name: fileName,
    blob: fileBlob,
    date: Date.now()
  });
  
  // Save back under their PIN namespace
  await db.files.put(userKey, userFiles);
}

async function loadUserFiles(pin) {
  const userKey = `user_${pin}`;
  const data = await db.files.get(userKey);
  return data ? data.files : [];
}
⚠️ The Reality Check

This is privacy by obscurity, not real security. Anyone who opens DevTools → Application → IndexedDB can see all user records and their raw data. It's great for casual household separation, but don't store anything you'd need a lawyer to protect. For real multi-user security, you need a server with actual authentication and encryption.
