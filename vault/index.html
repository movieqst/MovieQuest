What you're seeing isn't actually browser memory in the traditional sense—it's persistent storage that web apps use to save data on your device even after you close the tab or restart your computer.
Here's what's likely happening behind the scenes:

1. The browser has multiple "layers" of storage

RAM (Memory) — This is temporary. When you close the tab or browser, anything held only in RAM disappears instantly. This is what people usually mean by "memory."
Persistent Storage — This is saved to your actual hard drive/SSD. Several technologies allow websites to write data locally:
  • LocalStorage — Simple key-value storage (about 5–10 MB). Good for text and settings, but stores everything as strings.
  • IndexedDB — A full database built into the browser. Can store large amounts of structured data, including images and documents (often hundreds of MB or more depending on the browser).
  • Cache API / Service Workers — Used to store files and assets offline.

2. Images and documents need special handling

If you drop an image into a web app and it persists, the app is likely:
  • Converting the image to base64 (a text representation) and storing it in IndexedDB or LocalStorage
  • Storing it as a binary blob in IndexedDB
  • Or (most likely for professional document apps) silently syncing to the cloud and retrieving it when you return

3. The "I didn't save it" illusion

Many modern web-based document programs (like Google Docs, Notion, or specialized editors) use auto-save combined with one or more of these strategies:
  • Local-first: They save every keystroke to IndexedDB on your computer. When you return next week, the app loads from that local database.
  • Cloud sync: They quietly upload changes to a server in the background. Your "document" is actually being saved continuously—you just never pressed a manual Save button.
  • Hybrid: They save locally and sync to the cloud. If you're offline, it works from local storage; when you reconnect, it syncs.

4. How to tell which one is being used

If you want to check what's actually happening:
  • Open your browser's DevTools (F12 or Ctrl+Shift+I), go to the Application tab, and look under Storage → IndexedDB or Local Storage. You may see your document data sitting there.
  • Try opening the site in Incognito/Private mode or a different browser. If the document isn't there, it's likely stored locally in your original browser. If it is there, the app is saving to a server account.

The short version

Your browser isn't "remembering" it in memory—the website is saving it to your hard drive through IndexedDB or syncing it to a server automatically. The app just hides the save process from you so it feels seamless.

The user is asking a follow-up about whether storing data locally via browser persistent storage (IndexedDB, LocalStorage, etc.) consumes computer memory/RAM. This is a good question because there's often confusion between RAM (volatile memory) and disk storage (persistent storage).

  4. The storage itself is on disk, so it doesn't consume RAM when not in use, but the browser process itself uses RAM
  5. There's also a distinction between "storage quota" (disk space) and "memory" (RAM)
I should explain this clearly, distinguishing between:
  • Disk storage (where the data is permanently saved)
  • RAM (used when the page is active)
  • Browser memory management (tab suspension, garbage collection)
  • The concept of "memory pressure" and how browsers handle it
Let me give a clear, practical answer.
Yes, it does—but not in the way most people mean when they say "memory."
There's a crucial distinction between two things your computer uses:

1. Disk Storage (where your document actually lives)

When a website saves your document locally via IndexedDB or LocalStorage, it writes that data to your hard drive or SSD—the same place your files, photos, and apps live.
  • This is not RAM. It doesn't disappear when you restart.
  • It takes up disk space, not "memory" in the computer-science sense.
  • Your browser has a storage quota (usually a few gigabytes per website).

2. RAM (working memory)

This is the fast, temporary memory that gets wiped when you shut down. Here's how your document interacts with RAM:
When the website is open and active:
  • The browser loads your document from disk into RAM so you can edit it.
  • The more images/text in your document, the more RAM that tab uses.
  • If you have a huge document with lots of images, that single browser tab might use hundreds of megabytes of RAM.
When you close the tab:
  • The RAM is freed up (eventually). The browser's garbage collector reclaims it.
  • The document itself remains safely on your disk, ready to load again next week.
When you close the browser entirely:
  • All RAM is released.
  • The saved document is still on your disk. Next time you visit the site, it loads from disk back into RAM.

So what's the real answer?

Storing the document locally → uses disk space (permanent, cheap, abundant).
Using the document → uses RAM (temporary, faster, more limited).
If you never visited that website again, the data would still sit on your disk taking up a tiny sliver of storage, but zero RAM because nothing is actively running.

One more thing: Browser "memory" pressure

Modern browsers are smart about RAM. If you have 30 tabs open and your computer starts running low on RAM, the browser may suspend background tabs—essentially putting them to sleep and freeing their RAM—while keeping them open. When you click back to that tab, it reloads the data from disk (or its own cache) back into RAM.
Bottom line: Your document lives on your hard drive. It only costs RAM when you're actively looking at it.
